## Decisões técnicas (e por quê)

- **Firestore em São Paulo, no Spark:** o console não pediu cartão; a alternativa `nam5` só seria usada se pedisse. Backups programados exigem o Blaze, então ficaram de fora (o export em JSON está nas ideias para depois).
- **SDK do Firebase pela CDN (12.0.0), sem npm:** a especificação pede JS puro sem build.
- **Login por popup, não redirect:** o site e o `authDomain` ficarão em domínios diferentes, e o redirect depende de armazenamento de terceiros.
- **Subdomínio próprio `vault.msr-dev.com.br`:** no endereço padrão do GitHub Pages, o app dividiria a origem com o portfólio (`portfolio.msr-dev.com.br` usa o site de usuário), e scripts desses sites poderiam ler a sessão do Firebase. Ordem segura de configuração (verificar o domínio no GitHub antes de criar o CNAME) anotada na especificação.
- **Todo texto do usuário entra no DOM como texto (função `h()`):** evita XSS em comandos com `<`, `>`, `&`. O botão Abrir só aceita `http(s)://`.
- **Leitura de todos os itens em tempo real e busca no navegador:** a busca é global, e o volume é pequeno (uso pessoal).
- **Projeto criado direto no formulário,** com comparação de nomes sem maiúsculas e acentos.
- **Edição com `updateDoc` só dos campos editáveis:** preserva `tipo`, `origem`, `vezesCopiado` e `criadoEm`.
- **Contagem de cópias com `increment(1)`** e ordem pelos mais copiados.
- **Setas e Enter só agem na busca ou fora de campos, botões e links,** para não roubar o teclado de quem navega com Tab.
- **Restrição pelo UID, não pelo e-mail (R-01):** o `firestore.rules` vai para um repositório público; o UID não identifica a pessoa. O revisor tinha sugerido um e-mail que nem era o da conta usada.
- **Cofre "só cria" nas regras (`allow read, create`):** sobrescrever o salt ou o verificador deixaria todas as senhas ilegíveis. Trocar a senha mestra no futuro vai exigir mudar essa regra.
- **Criptografia:** PBKDF2-SHA256 com 600.000 iterações, chave AES-GCM 256 não exportável só na memória, IV novo a cada gravação, verificador para conferir a senha mestra. Senha mostrada some em 30 s; mínimo de 12 caracteres na senha mestra; recusa configuração com menos de 100.000 iterações.
- **Teste da criptografia no Node puro** (`node testes/cripto.test.mjs`, 14 verificações), sem instalar framework de testes.
- **Servidor de desenvolvimento próprio** (`ferramentas/servidor_dev.py`) com `Cache-Control: no-store`.

### Decisões técnicas (e por quê)
- **Referenciador da API key:**
  - Usei o endereço exato `http://localhost:5500/*`, porque o `localhost:*` foi recusado pelo Google (`API_KEY_HTTP_REFERRER_BLOCKED`).
  - O `firebaseapp.com` precisa estar na lista, senão o login por popup quebra.
  - Mudar a porta do servidor local exige atualizar a restrição.
- **Proteção contra iframe:** feita em JS no fim do `app.js`, e não com o script de redirecionamento sugerido. A CSP sem `'unsafe-inline'` bloquearia o script no `<head>`, e o redirecionamento falha com iframe `sandbox`.
- **Autoexclusão de terceiros:** `deleteUser` no próprio login, em vez de bloquear o cadastro, que exigiria o Identity Platform pago.
- **PWA sem service worker:** o Chrome não exige mais para instalar. Num cofre de senhas, um cache atrasaria correções de segurança, sem dar uso offline de verdade (o Firestore e o SDK vêm da internet).
- **Script da etapa 8 versionado no repositório** (a especificação dizia "fora dos repositórios"): assim tem histórico e passa por revisão. A chave fica fora.
- **Validação no script (D2)**, porque o Admin SDK ignora as regras:
  - só aceita os campos permitidos, com os limites do formulário;
  - recusa textos com cara de segredo;
  - nunca altera senhas;
  - item criado no app só é alterado com `--atualizar-item-do-app`, depois da confirmação do Mateus;
  - decide antes de criar o projeto, para uma recusa não deixar projeto vazio.
- **Testes com `unittest` e Firestore falso** (sem instalar `pytest` nem o SDK no Python do sistema). O `gravar()` recebe o montador de filtro como parâmetro, para os testes não precisarem do `FieldFilter`.
- **Skills globais:** a `guardar-comando` e o passo da `encerrar` servem a qualquer projeto. Cada projeto pode ter no `CLAUDE.md` a linha "Nome do projeto no Dev Vault: **Nome**", para o nome não variar e não duplicar projetos no app.

### Problemas resolvidos
- **Login quebrou depois de restringir a API key** → o `localhost:*` não casava com o referenciador → troquei pelo endereço exato → ao mudar a porta, atualizar a restrição.
- **Certificado HTTPS do Pages parado por 30 min** → removi e cadastrei de novo o domínio no Pages (via API) → saiu em minutos.
- **Push recusado (non-fast-forward)** → o GitHub cria um commit com o arquivo `CNAME` ao configurar o domínio → `git pull --rebase` antes do push.
- **`UserWarning` do `where()` posicional no `firebase-admin` 7** → passei a usar `where(filter=FieldFilter(...))` (R-04) → sempre rodar o teste real com `2>&1`.
- **Entrada padrão em cp1252 no Windows** (o modo `-` do script corromperia os acentos) → leitura em bytes decodificada como UTF-8, aceitando BOM → um teste cobre o caso.
